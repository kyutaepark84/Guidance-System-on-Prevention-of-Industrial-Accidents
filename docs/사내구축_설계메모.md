# 사내 시스템 구축을 위한 설계 메모 (DEMO 기준)

DEMO 테스트 결과를 반영하여 사내 시스템으로 옮길 때 참고할 데이터 구조·상태·연동 지점을 정리합니다.

## 1. 상태(State) 전이

```
                     ┌──────────── 정보수정/재판정 ────────────┐
[등록] ─판정─┬─ NOT_TARGET (일반, 비대상)                      │
             ├─ MONITORING (단가, 누계관리) ── 누계 1억 도달 ──┤
             └─ (대상) ────────────────────────────────────────┴─▶ DOCS_REQUESTED  ◀─ 보완요청 ─┐
                                                                       │ 협력업체 자료 제출       │
                                                                       ▼                         │
                                                                 DOCS_SUBMITTED ─────────────────┘
                                                                       │ 기관 기술지도 계약서 제출
                                                                       ▼
                                   ┌──────────────────────────▶  ACTIVE  ── 종결(관리부서) ──▶ CLOSED
                                   │ 기관 추가계약서                │ 연장 요청
                                   └──────────── EXTENSION ◀────────┘
                                       (구매 → 협력업체 → 기관 순서)
```

기술지도 회차(visit) 상태: `SCHEDULED → DONE` 또는 `SCHEDULED → IMPROVEMENT_REQUESTED ⇄ IMPROVEMENT_SUBMITTED → CLOSED_OK`, `CANCELED`

## 2. 주요 엔티티 (RDB 전환 시 테이블 후보)

| 엔티티 | 주요 컬럼 |
|---|---|
| PROJECT(공사) | 계약번호, 공사계약명, 구분(일반/단가), 업체ID, 계약시작/종료, 계약금액, 담당부서, 담당자, 기술지도기관ID, 상태, 기술지도 대상기간(시작/종료), 판정결과·근거, 대상전환일 |
| SETTLEMENT(정산실적) | 공사ID, 정산월(YYYY-MM), 금액, 출처(파일/SAP), 등록자 |
| TG_CONTRACT(기술지도 계약) | 공사ID, 계약일, 계약번호, 예정횟수, 노동부 제출일, 안전보건 확인 |
| WORK_DAY(작업일) | 공사ID, 일자 |
| VISIT(기술지도 회차) | 공사ID, 회차, 예정일/시간, 실시일, 지도요원, 내용, 보완요구, 개선기한, 노동부 제출여부, 상태 |
| IMPROVEMENT / REVIEW | 회차ID, 내용, 첨부, 일자, 작성자, (검토)승인여부 |
| EXTENSION(연장) | 공사ID, 차수, 사유, 단계, 변경 종료일/금액, 계약서 구분 |
| ATTACHMENT(첨부) | 공사ID, 구분(공사계약서/산재/사업자/기술지도계약서/결과/연장…), 참조ID, 파일 |
| NOTIFICATION(발송) | 공사ID, 이벤트, 채널(메일/SMS), 수신자, 제목, 본문, 발송결과 |
| HISTORY(이력) | 공사ID, 일시, 사용자, 역할, 처리내용, 비고 |
| FLAG(중복발송 방지) | 공사ID, 키(예: END_NOTICE:2026-12-31) |

## 3. 연동 지점

| DEMO | 사내 구축 시 |
|---|---|
| 계약서 Upload → 규칙 기반 추출 (`server/extract.js`) | 구매시스템 계약 정보(계약번호·명·업체·기간·금액·단가여부) 인터페이스 |
| 월별 정산실적 엑셀 Upload (`server/settlement.js`) | SAP 단가 정산 누계 데이터 일배치 연동 |
| 메일/SMS 기록 (`server/notify.js` `deliver()`) | 사내 메일서버(SMTP)·SMS/알림톡 게이트웨이 |
| 사용자 선택 로그인 | SSO + 협력업체/기관 외부 계정(포털) |
| 스케줄러 (`workflow.dailyCheck`, 매시간 날짜 변경 시 실행) | 배치 스케줄러(일 1회 오전) |

## 4. 테스트 시 확인할 사항 (개선사항 도출용 체크리스트)
- [ ] 우리 회사 실제 계약서 양식에서 자동 추출이 잘 되는지 (라벨 명칭 추가 필요 여부)
- [ ] 판정 기준: 부가세 포함/별도 금액 기준, 단가계약 '연간' 누계의 기준(역년 vs 계약년도)
- [ ] 협력업체 제출 필수자료 목록 (현재: 공사계약서·산재보험 가입증명서·사업자등록증)
- [ ] 안내 수신자 범위(부서 전체 vs 담당자), SMS 문구 길이
- [ ] 기술지도 주기 사전안내 시점(현재 직전 지도 후 10일 경과 시), 만료 사전안내(D-15)
- [ ] 노동부 제출(계약서·결과) 확인 책임 주체
- [ ] 연장 단계별 필수 서류 구성
